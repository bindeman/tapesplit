TapeSplit watches your digitized VHS and camcorder tapes so you don't have to. It splits hours of unlabeled footage into moments, works out when each one happened, where, and who was there, and leaves anything it isn't sure about in a review queue for you.

The idea

What's on tape 16?

Most families have a box like this somewhere. Getting it digitized gets you a folder of two-hour files called tape-18.mp4, with no dates, no names, and no way to find the afternoon you remember.

TapeSplit does the part nobody has time for: watching all of it. Below is one real tape, split. It holds two trips and a spring at home. The camcorder never said so; the footage did.

How it works

Four passes over every tape

One command runs the whole pipeline. Each stage checks what your machine can do, skips with a reason when it can't, and picks up where it stopped if you run it again.

Watch

Runs on your Mac
  • Scene cuts from ffmpeg, with blue screen, black frames and static thrown out.
  • Every word transcribed by whisper.cpp, in whatever language was spoken.
  • Voices separated with pyannote, then matched to people from context and known voice samples.
  • Text in the picture read by Apple Vision, including the camcorder's own date stamp.
  • Every face followed through each shot and clustered into people with InsightFace.

Understand

Cloud, optional
  • Gemini watches each tape in chunks and proposes events with timestamps: what happened, who is there, where and when.
  • Priced before it runs. Each batch is estimated first and capped by --max-cloud-usd.
  • Optional by design. Without it, TapeSplit still builds a timeline from local signals.

Reconcile

Runs on your Mac
  • Every signal becomes a claim that keeps its source: a transcript line, a frame, a face track.
  • Events are stitched across chunks and dated from stamps, speech and context.
  • Names are reconciled. Mom, Katya and Катя become one person; home in 2003 and home in 2006 stay two places.
  • A blind verifier re-checks a sample of claims against the clips themselves.

Review

You, a few minutes
  • Strong guesses are accepted automatically, under safety rules for each kind of fact.
  • The rest wait in a queue with the evidence and the clip one click away.
  • Your fixes are kept apart and replayed on every rebuild, so re-running never undoes them.
$ tapesplit auto ~/Tapes

That's the whole pipeline: 21 stages, resumable, cost-capped, with the safe auto-accept pass near the end. tapesplit doctor shows which stages your machine can run.

ingest → exif → non-content → scenes → transcribe → diarize → gemini → core-build → visuals → ocr → captions → visual-embed → visual-similarity → faces → face-tracks → face-cluster → reground → finalize → apply-suggestions → semantic-embed → verify

Built to be checked

It shows its work

Family history is easy to get wrong and hard to un-learn. TapeSplit treats every label as a claim with evidence, and makes being wrong cheap to fix.

Guesses look like guesses

Inferred facts read "appears to be…", carry a confidence, and link to the transcript line, frame or face track they came from.

Auto-accept has rules

Each kind of fact has its own confidence floor. A relationship is only accepted when both people are resolved and the evidence agrees.

Your fixes stick

Corrections live in their own file and are replayed after every rebuild. Re-run the pipeline as often as you like.

It measures itself

A blind verifier samples claims and checks them against the clips, and per-module precision decides when new logic ships.

Your tapes stay home

Every stage has a local path. Cloud stages are opt-in, estimated before they run, and capped at a dollar amount you set.

Plain files underneath

A project is a folder of JSONL files, a SQLite search index and thumbnails. Nothing is locked inside the app.

Get started

Run it on your tapes

TapeSplit is best tested on Apple Silicon Macs. Linux runs everything except the Apple Vision stages, which fall back to OpenCV. You need Python 3.11+ and ffmpeg.

Terminal
# install
brew install ffmpeg
git clone https://github.com/bindeman/tapesplit
cd tapesplit
python3.12 -m venv .venv
.venv/bin/pip install -e \
  '.[local-ai,vision,macos,visual-ai,face-ai,speaker-ai]'

# check what this machine can run
.venv/bin/tapesplit doctor

# tapes in, archive out
.venv/bin/tapesplit auto ~/Tapes

# browse and review
.venv/bin/tapesplit ui ~/Tapes.tapesplit

tapesplit auto ~/Tapes --plan prints what would run without running it. --profile local never calls a cloud service.

Keys go in a .env file next to the code; copy .env.example to start. Every key is optional.

Questions

Before you dig out the box

Do my videos leave my computer?

Only if you turn on a cloud stage. Gemini analysis uploads low-resolution proxies to a Cloud Storage bucket in your own Google Cloud project; the Azure stages send individual frames and audio snippets. With --profile local, nothing leaves your machine.

Which files does it take?

Anything ffmpeg can read: MP4, MOV, MKV, AVI, DV, MPEG, VOB and M2TS. One file per tape works best, since a tape's own timeline is part of the evidence.

Does it handle more than one language?

Yes. The sample archive is a mix of Russian and English. Transcripts keep the original language, search works across both, and Journal quotes stay verbatim with a translation alongside.

How does it know when something was filmed?

It combines the camcorder's burned-in date stamp (read from the frame), dates spoken on tape, Gemini's reading of the scene, and the order of events on the tape. When those disagree, the date stays a reviewable guess instead of a fact.

Is it finished?

It's an alpha. The pipeline runs end to end on a real archive, and the review queue exists because it still makes mistakes, like the occasional place borrowed from the wrong era. Issues and pull requests are welcome.
